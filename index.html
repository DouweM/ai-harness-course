Harness engineering with Pydantic AI

An agent is a model plus its harness: the instructions, the tools, the history you keep, and the code that decides what happens next. Harness engineering is improving that harness one idea at a time. You design it from the model's side, by reading its page and spotting what it is missing; you build the idea with Pydantic AI; and you measure it against what you have: which is better, by how much, on which cases. Starting from scratch is just the first lap.

  1. Design it from the model's sidePart 1: How the model sees the world. What it can see, whose voice it trusts, how its world stays current. Where ideas come from.
  2. Build it with Pydantic AIPart 2: Building it with Pydantic AI. One collections agent through one customer's week: instructions, tools, history, the answer form, then all of it as one capability, behind more agents, more doors and tests.
  3. Measure what worksPart 3: Production, and measuring what works. Production, model choice, evals, and your own probes.

Afterwards, your team can read any agent's page the way its model does and name what's missing, build the fix as a reusable Pydantic AI capability, and show with a two-arm comparison on your own cases whether it beat what you had.

Presenting it

Press P on any page for talk mode. Prose folds away, and transcripts, predictions and results fill the screen. → or a clicker moves between stops and on to the next chapter, R reveals, 1 to 4 pick an answer for the room, N shows speaker notes.

With your coding agent

Open your coding agent in this repo (clone it here). Every chapter has an Ask your agent button that copies a prompt naming the chapter. Your agent reads AGENTS.md, which maps each chapter to notes, docs and runnable code. Ask it to go deeper, to map the chapter onto your own agent, or to run the code with you.

Pydantic AI is open source (MIT). Results in this course come from our own small, dated runs on the models named; read them as big effects only, and re-run before you build on a number.
