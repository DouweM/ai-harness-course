Harness engineering with Pydantic AI

An agent is a model plus its harness: its instructions, tools, history, and the code that decides what happens next. Harness engineering improves that harness. Design from the model's side by reading its page (everything it receives for one request: instructions, tool definitions, and conversation) and spotting what's missing. Build with Pydantic AI, then measure against your current version: which is better, by how much, and on which cases. Repeat the loop.

  1. Design it from the model's sidePart 1: How the model sees the world. What it sees, whose voice it trusts, and how its world stays current. Find ideas for improvement.
  2. Build it with Pydantic AIPart 2: Building it with Pydantic AI. Build a billing agent: instructions, tools, history, answer form, capabilities, more agents, interfaces (chat, web, phone), and tests.
  3. Measure what worksPart 3: Production, and measuring what works. Production, model choice, evals, and probes.

Afterwards, your team can read an agent's page from the model's view, find what's missing, build a reusable Pydantic AI capability, and compare versions on your own cases.

Get the code

Clone the repo to run each "Run it" command. You need git and uv; uv installs Python 3.11+ and dependencies. Examples use offline stand-in models, with no API key. Real model runs need that provider's key.

git clone https://github.com/DouweM/ai-harness-course
cd ai-harness-course
uv sync

Presenting it

Press P for talk mode: prose folds away, and transcripts, predictions, and results fill the screen. Use → or a clicker to move between stops and chapters, R to reveal, 1 to 4 to choose, and N for speaker notes.

With your coding agent

Open your coding agent in this repo (clone it here). Each chapter's Ask your agent button copies a prompt naming the chapter. The agent reads AGENTS.md, which links chapters to notes, docs, and runnable code. Ask it to explain a concept, apply it to your agent, or run the code with you.

Pydantic AI is open source (MIT). Results come from small, dated runs on the named models; treat them as large effects and re-run before relying on a number. This site uses Pydantic Logfire to track which pages people read and where they stop, so we can clarify confusing parts.
