Part 3 · Production, and measuring what works

Run your own probe

Every prediction in this course came from a probe. Change one thing, predict in writing, run it a few times, and read what the model wrote. Ten minutes, a few cents, and you can rerun it when the models change.

# 3. ARMS: both hide mark_paid during close; only one says so
async def hide_mark_paid(ctx: RunContext[Deps], tools: list[ToolDefinition]) -> list[ToolDefinition]:
    return [t for t in tools if t.name != 'mark_paid']


def make_agent(arm: str, model: str) -> tuple[Agent, Deps]:
    agent = Agent(
        model,
        deps_type=Deps,
        instructions="You handle customers' emails about their invoices with us.",
        output_type=[str, DeferredToolRequests],
        capabilities=[billing_world, PrepareTools(hide_mark_paid)],
    )
    billing = FakeBilling()
    billing.invoices['INV-2050'] = billing.invoices['INV-2050'].model_copy(update={'status': 'paid'})  # as Tuesday left it
    closing = arm == 'hidden, and said'  # deps.closing turns on billing_world's appended close notice
    return agent, Deps(billing=billing, received=CLOSE_STARTS, closing=closing)


ARMS = ['hidden, quietly', 'hidden, and said']


# 4. SCORE
def score(reply: str) -> str:
    text = reply.lower()
    if text.startswith('[asked for approval'):
        return 'worked around it: record_payment'
    if re.search(r'\b(has been|is now|i\'ve|i have|now) (been )?marked\b', text):
        return 'claimed it was done'
    if re.search(r'\b(month-end|close is|close,|close\b.{0,20}monday|until monday)', text):
        return 'said why: close'
    return 'failed, no reason'

Why we believe a null result

"Nothing changed" only counts if the probe could have seen a change. A positive control (clear the results the task needs) moved re-reads by 89 points, and a manipulation check on forked copies found the anomalies were noticed (50 to 88% per type, against 12% on clean histories). So the models saw it, and compartmentalised. The limit: the tasks were easy.

One real spill-over: an account change that arrived without its promised notice made Claude Sonnet 5.5 re-check the account it was about to act on in 5 of 10 runs. And a "repair" note saying a write was lost made it redo the write: a fix is also an event.

Five habits

  1. Change one thing. Two at once and you learn about neither.
  2. Predict in writing. Our close prediction was wrong; that's the best line in the table.
  3. Prove the probe can see. A control that must move, and a check that the change reached the model.
  4. Read cases, not rates. Reading them caught a flaw in our own setup, and showed what "worked around it" meant: a 4,120.00 payment nobody saw.
  5. Small n, big effects only. 0 of 10 against 10 of 10 is a finding; 7 against 9 means run more.
