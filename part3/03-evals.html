Evals and experiments

If people correct your agent today, their corrections are your eval set: the test cases you compare versions on. If nobody does yet, label 20 cases from your traces. Run the old way and the new way on them, and judge both on the mistake that costs you, case by case.

The dataset you already have

Each correction creates a labeled case: a real input and the answer the team stands behind. Export 20 cases for a dataset. For Dana's billing agent, an email about INV-2041 is one such case. Pick evaluators, the checks that score each answer, to ask whether it matches the team and avoids the expensive mistake: recording a promise the customer never made.

code/part3/ch3_evals.py · pydantic-evals 2.x
def corrections_dataset() -> Dataset[Email, bool, dict[str, Any]]:
    rows = [json.loads(line) for line in (DATA / 'corrections.jsonl').read_text().splitlines()]
    return Dataset[Email, bool, dict[str, Any]](
        name='promise-routing',
        cases=[
            Case(name=r['id'], inputs=Email(text=r['email']), expected_output=r['is_commitment'], metadata=r)
            for r in rows
        ],
        evaluators=[DecidedLikeTheTeam(), NoPromiseNobodyMade()],
    )


@dataclass
class DecidedLikeTheTeam(Evaluator[Email, Decision]):
    def evaluate(self, ctx: EvaluatorContext[Email, Decision]) -> bool:
        return ctx.output.writes == ctx.expected_output


@dataclass
class NoPromiseNobodyMade(Evaluator[Email, Decision]):
    """The expensive mistake: a promise in the ledger that the customer never made."""

    def evaluate(self, ctx: EvaluatorContext[Email, Decision]) -> bool:
        return not (ctx.output.writes and not ctx.expected_output)

Two arms: the agent before Part 2, and after

An experiment compares versions, called arms, on the same cases. Arm A follows Part 1 chapter 1: one call returns JSON with a confidence, and scores of 70 or more go to the ledger. Arm B follows Part 2: a typed answer form, lookup tool, and code that writes only promises made to us for known invoices. Its form adds addressed_to_us (who the promise is for) and evidence (the email words that support the answer; code/part3/eval_world.py). This is promise_router, the classifier specified in chapter 2.

Arm B changes several things, so this chapter asks whether the change helped and on which cases. Chapter 4 measures one idea at a time.

code/part3/ch3_evals.py · the two tasks
def make_tasks(model_for: Any):
    async def single_shot_call(email: Email) -> Decision:
        result = await single_shot.run(email.text, model=model_for('a', email))
        record_cost(result)
        reply = json.loads(result.output.strip().removeprefix('```json').removesuffix('```'))
        writes = bool(reply['is_commitment']) and reply['confidence'] >= 70
        return Decision(writes, f'is_commitment={reply["is_commitment"]}, confidence={reply["confidence"]}')

    async def typed_agent(email: Email) -> Decision:
        result = await agent.run(email.text, model=model_for('b', email))
        record_cost(result)
        out = result.output
        if out.is_commitment and out.addressed_to_us and out.invoice_number in INVOICES:
            return Decision(True, f'commitment to us for {out.invoice_number}')
        if out.is_commitment and out.addressed_to_us:
            return Decision(False, 'commitment without a known invoice: sent to a person')
        return Decision(False, 'not a commitment to us')

baseline = await dataset.evaluate(single_shot_call, name='A: single-shot call')
report = await dataset.evaluate(typed_agent, name='B: typed agent')
report.print(baseline=baseline, include_input=True)

In Logfire, and on live traffic

With logfire.configure(), each evaluate() call is an experiment in Logfire, with a link from each case to its trace. In CI (tests run on every pull request), Pydantic Evals records the branch and commit for comparison with the base. The OnlineEvaluation capability also runs evaluators that need no label on sampled production traffic in the background:

code/part3/ch3_online_evals.py
class EvidenceQuotesTheEmail(Evaluator):
    """A commitment must quote words that are actually in the email."""

    def evaluate(self, ctx: EvaluatorContext) -> bool:
        out: PaymentCommitment = ctx.output
        return not out.is_commitment or bool(out.evidence and out.evidence in str(ctx.inputs))


agent = Agent(
    TestModel(custom_output_args={'is_commitment': True, 'addressed_to_us': True, 'evidence': 'paid this Friday'}),
    name='promise_agent',
    output_type=PaymentCommitment,
    capabilities=[
        OnlineEvaluation(
            evaluators=[OnlineEvaluator(evaluator=EvidenceQuotesTheEmail(), sample_rate=1.0)],
            config=OnlineEvalConfig(default_sink=print_sink),
        )
    ],
)
Go deeper: habits that make the comparison trustworthy

When outputs vary, run each case more than once (repeat=3). Add surprising corrections as cases. For an online LLM judge, set a small sample_rate and concurrency cap. Await wait_for_evaluations() on shutdown to save pending scores. Add cases flagged by online evals to the dataset.
