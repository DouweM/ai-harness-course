Evals and experiments

If people correct your agent today, their corrections are your eval set. If nobody does yet, label 20 cases from your traces. Run the old way and the new way on them, and judge both on the mistake that costs you, case by case.

The dataset you already have

Every time someone fixes what your agent or an older LLM call decided, they label a case: a real input and the answer they stand behind. Export 20 and you have a dataset. Dana's week alone gave you three: Tuesday's promise, Wednesday's correction and Friday's dispute. Ours has emails like those and more. Then pick evaluators for two questions: did it decide like the team, and did it make the expensive mistake? Here that is a promise in the ledger the customer never made.

def corrections_dataset() -> Dataset[Email, bool, dict[str, Any]]:
    rows = [json.loads(line) for line in (DATA / 'corrections.jsonl').read_text().splitlines()]
    return Dataset[Email, bool, dict[str, Any]](
        name='promise-routing',
        cases=[
            Case(name=r['id'], inputs=Email(text=r['email']), expected_output=r['is_commitment'], metadata=r)
            for r in rows
        ],
        evaluators=[DecidedLikeTheTeam(), NoPromiseNobodyMade()],
    )


@dataclass
class DecidedLikeTheTeam(Evaluator[Email, Decision]):
    def evaluate(self, ctx: EvaluatorContext[Email, Decision]) -> bool:
        return ctx.output.writes == ctx.expected_output


@dataclass
class NoPromiseNobodyMade(Evaluator[Email, Decision]):
    """The expensive mistake: a promise in the ledger that the customer never made."""

    def evaluate(self, ctx: EvaluatorContext[Email, Decision]) -> bool:
        return not (ctx.output.writes and not ctx.expected_output)

Two arms: before Part 2, and after

Arm A is the simplest version of Part 1 chapter 1's agent: one call returning JSON with a confidence, written to the ledger at 70 or more. Arm B is the kind of agent Part 2 builds: a typed answer form, a lookup tool, and code that writes only a promise made to us, for an invoice we know. Its form has two fields Part 2's doesn't: addressed_to_us, whether the promise is made to us rather than to someone else, and evidence, the email's own words that back the answer (code/part3/eval_world.py). This is promise_router, the classifier chapter 2 froze specs for.

That is a rewrite, not one change, so this chapter answers "did the move pay off, and on which cases?". Measuring one idea at a time is chapter 4.

code/part3/ch3_evals.py · the two tasks
def make_tasks(model_for: Any):
    async def single_shot_call(email: Email) -> Decision:
        result = await single_shot.run(email.text, model=model_for('a', email))
        record_cost(result)
        reply = json.loads(result.output.strip().removeprefix('```json').removesuffix('```'))
        writes = bool(reply['is_commitment']) and reply['confidence'] >= 70
        return Decision(writes, f'is_commitment={reply["is_commitment"]}, confidence={reply["confidence"]}')

    async def typed_agent(email: Email) -> Decision:
        result = await agent.run(email.text, model=model_for('b', email))
        record_cost(result)
        out = result.output
        if out.is_commitment and out.addressed_to_us and out.invoice_number in INVOICES:
            return Decision(True, f'commitment to us for {out.invoice_number}')
        if out.is_commitment and out.addressed_to_us:
            return Decision(False, 'commitment without a known invoice: sent to a person')
        return Decision(False, 'not a commitment to us')

baseline = await dataset.evaluate(single_shot_call, name='A: single-shot call')
report = await dataset.evaluate(typed_agent, name='B: typed agent')
report.print(baseline=baseline, include_input=True)

In Logfire, and on live traffic

With logfire.configure(), each evaluate() call is an experiment in Logfire, and each case links to its full trace. From CI, Pydantic Evals records branch and commit, so a pull request compares against its base. Evaluators that need no label also run on production traffic through the OnlineEvaluation capability, sampled, in the background:

code/part3/ch3_online_evals.py
class EvidenceQuotesTheEmail(Evaluator):
    """A commitment must quote words that are actually in the email."""

    def evaluate(self, ctx: EvaluatorContext) -> bool:
        out: PaymentCommitment = ctx.output
        return not out.is_commitment or bool(out.evidence and out.evidence in str(ctx.inputs))


agent = Agent(

Go deeper: habits that make the comparison trustworthy

Run each case more than once (repeat=3) when outputs vary. Add cases as corrections come in, especially the surprising ones. Give an LLM judge a small sample_rate and a concurrency cap online, and await wait_for_evaluations() on shutdown so pending scores aren't lost. The cases online evals flag are next month's dataset.
