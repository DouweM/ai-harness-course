The loop

The three parts are one loop. Design from what the model is missing, build one idea for it, measure it against what you have on your own cases, and let the misses become the next idea.

One loop, three steps

Every dot is a chapter you've read; the filled one is this one. Tap a part to send Tok there.

Each step is weak alone. An idea you can't try is an opinion; a change nobody measured is a demo; an eval with no idea behind it says a number moved, not why. Most laps improve an agent you already run, and the winner is often a combination of ideas. Starting from scratch is just the first lap, where you try a few directions to see where the good region is.

A lap on your own agent

One lap on an agent you already run takes a day:

  1. Pick one decision someone corrects today, and export 20 or more corrections.
  2. Write the evaluator for the mistake that costs you.
  3. Run today's version as arm A and read every miss.
  4. Have one idea from what the misses share: what can't it see, whose voice is it, what moved?
  5. Implement it as one change, ideally one capability, and run it as arm B.
  6. Compare, and write down how much better B is on which cases, what you'd ship, what you'd watch online, and the next lap.

Bring the agent's code, read access to its traces or corrections, and a model API key. Your coding agent can do the typing; "Ask your agent" below hands it this chapter.
