More than one agent

Use the smallest shape that does the job. When an agent hands a sub-task to another agent, give that agent typed facts to return, and share the parent's usage counter with it, or your cost limit misses what the second agent spends.

Smallest shape first

The point: pick the smallest shape; when you delegate, return typed facts and share usage. The prediction: a cost limit that never sees the delegate's retries.

"The amount on INV-2041 looks wrong: we were quoted 3,900." A dispute stops reminders and promises, then routes the case to a person. Classifying the email is a narrow job for a smaller model.

An agent is a loop; each turn costs a request. Four shapes, from cheapest:

When the coordination itself is the work (check ten emails at once, keep the ones that found something, summarize those), one tool call per step is slow and fills the parent's context. The harness's DynamicWorkflow gives the model one tool instead: it writes a short Python script that calls your sub-agents as functions, the script runs in the Monty sandbox, and only what it returns reaches the parent. Each agent run counts its own usage. Without usage=, the classifier's 8 requests are invisible to the parent's limit. Retries or repeated delegation can exceed the parent's cost limit.

The fix: one line

Pass usage=ctx.usage to add the delegate's requests to the parent's total. Also pass usage_limits= so the delegate stops when it reaches the limit. SubAgents does both.
