Instructions and deps

Standing rules go in instructions=. Facts that change go in deps (the data your code passes into each run), and an instructions function writes them onto the page every request. A fact frozen into a string goes stale without anyone noticing.

The date that froze

The point: facts from your app belong in deps and an instructions function, not in an f-string at import. The stakes: a promise recorded for a Friday that already passed.

Dana's email asks the billing agent to handle INV-2041. Its prompt is a Python f-string with today's date, built once when the service starts, so the date goes stale while the service runs.

The agent records Friday 13 Nov, which has passed, and sends Dana an overdue reminder. The model followed its page: in Part 1, models given the date worked out the right Friday 15 times out of 15. The prompt was correct when deployed, then went stale silently.

No prediction here: everyone sees it coming. Spend the time on where the date comes from: the email's arrival, not the clock.

The fix: a fact from deps, every request

{{code ch2_instructions.py deps "code/part2/ch2_instructions.py · deps and an instructions function" keys="received: date|instructions='Decide|@agent.instructions|return f'"}} {{code ch2_instructions.py run "code/part2/ch2_instructions.py, both, side by side"}} {{out ch2_instructions}}

Offline, deterministic. A FunctionModel reads the email and works out "this Friday" from the date on its page, as in Part 1. Use the email's arrival date, which your code knows: using today's date could point to the wrong week if handling is delayed.

When a value changes mid-conversation

An instructions function runs before each request, so its line stays current. For a value that can change during a conversation, give it a name and use on_change='append'. The old instructions stay intact, and the change is added at the end when it happens. In Part 1 chapter 4, rewriting the top led some models to write as if following their own past (Grok and Qwen 0 of 24); appending worked on all six models shown, 24 of 24 each. Chapter 3 uses this for a tool that leaves.

What you can do now

Find f-strings and .format( in prompt code. Put each changing value in a deps field and instructions function. Give each value that can change mid-conversation a name and on_change='append'.
