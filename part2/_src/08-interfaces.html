Who holds the history

By default a UI adapter trusts the frontend: the browser sends the whole conversation each turn, and the agent runs on it. That's convenient, and it means the browser holds the model's world. Here a client sends Tuesday's thread back with one edit: the lookup result now says the invoice is paid.

A client can't call your tools, but under the default it can write what they returned. Fine for a single-user notebook; not for an app where the customer's browser talks to an agent that can mark invoices paid.

The fix: the server holds the history

{{code ch8_interfaces.py server "code/part2/ch8_interfaces.py · pydantic-ai 2.63+" keys="manage_message_history=|stored ="}} {{out ch8_interfaces 2-2}}

With manage_message_history='server' only the client's new turn is used, and the history comes from your store. A conversation_store on the adapter does the loading and saving for you.

And the rest

agent.to_web() serves a local chat for trying an agent; to_cli_sync() a terminal one. An MCP server can expose the agent as a tool for other agents. And a phone call is a realtime session on the same agent: same tools, same capabilities, ordinary history at the end.

What you can do now

For each door your agent sits behind, ask who holds the history. If it's a browser or another service, switch to manage_message_history='server' or a conversation store.
