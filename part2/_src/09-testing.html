A cheap adversary for your gates

The point: harness ideas are deterministic and testable without a model. TestModel calls every tool; the approval gate either holds or it doesn't.

Friday 20 Nov, 17:00Before the agent runs unattended over the weekend, the team wants proof that nothing writes to the ledger without a person, whatever the model does.

TestModel is a stand-in model that calls every tool it's offered, with arguments generated from their schemas, then answers. It doesn't judge anything; it pokes everything.

The gate held. Nothing reached the ledger. TestModel's made-up email id and invoice number got a ModelRetry, and it moved on: a bad argument becomes feedback, not a crash. record_payment's made-up invoice was rejected by its args_validator before anyone was asked (chapter 6), so only mark_paid waits for a person; it has no validator, so a person would be asked about invoice "a". If someone drops requires_approval from a tool next month, this test fails before the weekend does.

One test per idea

Every chapter's idea is a property of your code, so each gets a test. FunctionModel lets a test play the model: look at what the request offered, answer badly on purpose, check what comes back. Set ALLOW_MODEL_REQUESTS = False once, and any test that would reach a real model fails instead.
