A quick test that tries every tool

The point: harness ideas are deterministic and testable without a model. TestModel calls every tool; the approval gate either holds or it doesn't.

The team needs proof that no tool can write to the ledger without a person's approval, whatever the model does.

TestModel is a stand-in that calls every offered tool with made-up arguments matching its parameters, then answers. It doesn't judge; it tries every tool. Tool code really runs, so tests must use fake services, never your real ledger.

The approval rule held. Nothing reached the fake ledger. TestModel's made-up email id and invoice number got a ModelRetry: bad arguments become feedback, not a crash. record_payment's made-up invoice failed its args_validator before anyone was asked (chapter 6). Only mark_paid waits for a person; with no validator, it would ask about invoice "a". If someone removes requires_approval, this test fails before production.

One test per idea

Each chapter's idea is a property of your code, so give it a test. FunctionModel lets a test play the model: inspect the request, answer badly on purpose, and check the result. Set models.ALLOW_MODEL_REQUESTS = False in test setup so any test reaching a real model fails.

These offline tests check code and rules, not the model's judgment when reading Dana's email. That needs real models and cases, covered in Part 3.

What you can do now

Write one test per harness idea in your agent: each gate, notice and validator. Run TestModel against every agent that has a writing tool.

See it in Logfire. Under pytest, Logfire sends nothing by default. To assert on what a run did, the capfire fixture from logfire.testing captures its spans in the test.
