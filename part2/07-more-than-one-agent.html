More than one agent

Use the smallest shape that does the job. When an agent delegates, hand the delegate typed facts to return, and the parent's usage to count on, or your cost limit sees only half the bill.

Smallest shape first

The point: pick the smallest shape; when you delegate, return typed facts and share usage. The prediction: a cost limit that never sees the delegate's retries.

from pydantic import BaseModel

from pydantic_ai import Agent, RunContext, ToolOutput


class DisputeCheck(BaseModel):
    """The classifier's verdict: typed facts and doubts, so the parent's code can act on them."""

    is_dispute: bool
    invoice_number: str | None = None
    claimed_amount: str | None = None
    doubts: list[str] = []


classifier = Agent(
    'anthropic:claude-haiku-5-5',
    instructions='Decide whether this email disputes one of our invoices.',
    output_type=ToolOutput(DisputeCheck),
)
collections = Agent(
    'anthropic:claude-sonnet-5-5',
    instructions="You handle customers' emails about their invoices. Check for a dispute before recording a promise.",
)


@collections.tool
async def check_for_dispute(ctx: RunContext, email_text: str) -> DisputeCheck:
    """Ask the dispute classifier about an email."""
    result = await classifier.run(email_text, usage=ctx.usage)  # one usage count for the whole tree
    return result.output

What happened

It finished. The limit counted 5 requests; 13 were sent.

// output, recorded by verify.py
without usage=ctx.usage: finished; the limit counted 5 requests, 13 were sent

Each agent run counts its own usage. Without usage=, the classifier's 8 requests happened in runs of their own, invisible to the parent's limit. A delegate stuck retrying, or a model that keeps delegating, runs up a bill your ceiling never sees.

The fix: one line

Pass usage=ctx.usage, and the delegate counts on the parent's usage: the limit sees every request in the tree.

// output, recorded by verify.py
with usage=ctx.usage   : stopped: The next request would exceed the request_limit of 8

Offline, deterministic. Stand-in models for both agents; the counting is Pydantic AI 2.68's real behavior. SubAgents forwards usage by default.

Handing off to a person

A handoff doesn't need another agent. Make it an output type: the run ends with an Escalation, and your code routes it to the billing team's queue. Your code decides what happens next, and tests can check it.

code/part2/ch7_multi.py, a handoff as output
class Escalation(BaseModel):
    """Hand this email to a person on the billing team."""

    reason: str
    invoice_number: str | None = None


class Reply(BaseModel):
    """A reply we can send the customer as is."""

    text: str


triage = Agent(  # a handoff is an output type: the run ends, and your code routes it
    'anthropic:claude-sonnet-5-5',
    instructions='Answer the customer, or escalate when a person has to decide.',
    output_type=[ToolOutput(Reply, name='reply'), ToolOutput(Escalation, name='escalate')],
)

What you can do now

Find every place one of your agents runs another. Give each delegate a typed output and usage=ctx.usage, and set a usage limit on the outer run.
