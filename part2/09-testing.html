Testing

The model's judgment is Part 3's job. Everything around it is ordinary code, and every idea in this part gets a test that runs in a second, offline.

A quick test that tries every tool

The point: harness ideas are deterministic and testable without a model. TestModel calls every tool; the approval gate either holds or it doesn't.

Friday 20 Nov, 17:00Before the agent runs unattended over the weekend, the team wants proof that nothing writes to the ledger without a person, whatever the model does.

TestModel is a stand-in model that calls every tool it's offered, with made-up arguments that fit each tool's parameters, then answers. It doesn't judge anything; it just tries every tool. Your tool code really runs, so tests give it fake services, never your real ledger.

from pydantic_ai import DeferredToolRequests
from pydantic_ai.models.test import TestModel

from billing import CLOSE_STARTS, FakeBilling
from billing_world import Deps, reminders

deps = Deps(billing=FakeBilling(), received=CLOSE_STARTS)
with reminders.override(model=TestModel()):  # calls every tool it's offered, with generated arguments
    result = reminders.run_sync('INV-2041 is overdue.', deps=deps)

assert isinstance(result.output, DeferredToolRequests)
print('waiting for a person:', sorted(call.tool_name for call in result.output.approvals))
print('tool results sent back:', [p.tool_name for m in result.all_messages() for p in m.parts if p.part_kind == 'tool-return'])
print('ledger writes:       ', deps.billing.writes)
// output
waiting for a person: ['mark_paid']
tool results sent back: ['read_email', 'lookup_invoice', 'record_payment']
ledger writes:        []

The approval rule held. Nothing reached the (fake) ledger. TestModel's made-up email id and invoice number got a ModelRetry, and it moved on: a bad argument becomes feedback, not a crash. record_payment's made-up invoice was rejected by its args_validator before anyone was asked (chapter 6), so only mark_paid waits for a person; it has no validator, so a person would be asked about invoice "a". If someone removes requires_approval from a tool next month, this test fails before the change reaches production.

One test per idea

Every chapter's idea is a property of your code, so each gets a test. FunctionModel lets a test play the model: look at what the request offered, answer badly on purpose, check what comes back. Set models.ALLOW_MODEL_REQUESTS = False once in your test setup, and any test that would reach a real model fails instead.

models.ALLOW_MODEL_REQUESTS = False  # a test can never reach a real model, even by accident


def test_the_approval_gate_holds():
    """TestModel calls every tool with generated arguments: a cheap adversary for your wiring."""
    deps = Deps(billing=FakeBilling(), received=CLOSE_STARTS)
    with reminders.override(model=TestModel()):
        result = reminders.run_sync('INV-2041 is overdue.', deps=deps)
    assert isinstance(result.output, DeferredToolRequests)
    assert {call.tool_name for call in result.output.approvals} == {'mark_paid'}  # record_payment's made-up
    # invoice was rejected by its args_validator, before any person was asked
    assert deps.billing.writes == []  # nothing was written without a person


def test_close_hides_mark_paid_and_says_so():
    seen: list[AgentInfo] = []

    def look(messages: list[ModelMessage], info: AgentInfo) -> ModelResponse:
        seen.append(info)
        return ModelResponse(parts=[TextPart('No reminder during close.')])

    with reminders.override(model=FunctionModel(look)):
        reminders.run_sync('INV-2041?', deps=Deps(billing=FakeBilling(), received=CLOSE_STARTS, closing=True))
    assert 'mark_paid' not in [t.name for t in seen[0].function_tools]
    assert 'close is running' in seen[0].instructions

These offline tests check your code and its rules. What they can't tell you is whether the model's judgment is good: whether it reads Dana's email right. That needs real models and real cases, and it's Part 3.

What you can do now

Write one test per harness idea in your agent: each gate, notice and validator. Run TestModel against every agent that has a writing tool.

See it in Logfire. Under pytest, Logfire sends nothing by default. To assert on what a run did, the capfire fixture from logfire.testing captures its spans in the test.
