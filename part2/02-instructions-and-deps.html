Instructions and deps

Standing rules go in instructions=. Facts that change go in deps, and an instructions function writes them onto the page every request. A fact frozen into a string goes stale without anyone noticing.

The date that froze

The point: facts from your app belong in deps and an instructions function, not in an f-string at import. The stakes: a promise recorded for a Friday that already passed.

Tuesday 17 Nov, 09:02Dana's email arrives, and your billing system asks the agent about it. The agent's prompt was written the obvious way: an f-string with today's date, built when the module loads. The service was deployed last Thursday and hasn't restarted since.

from pydantic import BaseModel

from pydantic_ai import Agent, ToolOutput

from billing_world import read_email  # chapter 1's tool: Dana's email, as data


class PaymentCommitment(BaseModel):
    is_commitment: bool
    invoice_number: str | None = None
    due_date: date | None = None

The agent records Friday 13 Nov, a date that already passed, and the reminder schedule sends Dana an overdue reminder on Tuesday afternoon. The model did its job: the page says it is Thursday the 12th, and in Part 1, models given the date on their page worked out the right Friday 15 times out of 15. Nothing failed loudly. The prompt was right on deploy day and has been wrong since.

No prediction here: everyone sees it coming. Spend the time on where the date comes from: the email's arrival, not the clock.

The fix: a fact from deps, every request

code/part2/ch2_instructions.py · deps and an instructions function
from dataclasses import dataclass

from pydantic_ai import RunContext

from billing import FakeBilling


@dataclass
class Deps:
    billing: FakeBilling
    received: date  # when this email arrived: a fact your code knows, per run


agent = Agent(
    'anthropic:claude-sonnet-5-5',
    deps_type=Deps,
    instructions='Decide whether the customer email you are asked about commits to paying us.',  # standing: static
    output_type=ToolOutput(PaymentCommitment),
    tools=[read_email],
)


@agent.instructions  # rebuilt for every request, from this run's deps
def when_it_arrived(ctx: RunContext[Deps]) -> str:
    return f'The email was received on {ctx.deps.received:%A %Y-%m-%d}.'
code/part2/ch2_instructions.py, both, side by side
from billing import DANA_ID, RECEIVED, new_email

deps = Deps(billing=FakeBilling(), received=RECEIVED)  # Tuesday 17 Nov, five days after deploy
with baked.override(model=FunctionModel(reads_the_page)):
    print('baked at import:', baked.run_sync(new_email(DANA_ID), deps=deps).output.due_date)
with agent.override(model=FunctionModel(reads_the_page)):
    print('from deps:      ', agent.run_sync(new_email(DANA_ID), deps=deps).output.due_date)
// output
baked at import: 2026-11-13
from deps:       2026-11-20

Offline, deterministic. A FunctionModel stands in for the model: it reads the email, then works out "this Friday" from the date on its page, the way models did in Part 1. Use the date the email arrived, a fact your code knows, rather than today's: a queue that works through yesterday's mail would pick the wrong week.

When a value changes mid-conversation

An instructions function runs before every request, so its line is always current. For a value that can change while a conversation is open, like month-end close starting on Thursday, give it a name and on_change='append': the old instructions stay as they were, and the change arrives at the end of the page, at the moment it happened. Part 1 chapter 4 showed why: rewriting the top left some models writing like their own past (Grok and Qwen 0 of 24), while appending the change worked on all six models shown, 24 of 24 each. Chapter 3 uses this for a tool that leaves.

code/part2/ch2_instructions.py, a value that changes · pydantic-ai 2.59+
@dataclass
class CloseDeps(Deps):
    closing: bool = False  # month-end close is running


agent_with_close = Agent('anthropic:claude-sonnet-5-5', deps_type=CloseDeps, instructions='Handle this customer email.')


@agent_with_close.instructions(name='close', on_change='append')  # a value that can change mid-conversation
def close_notice(ctx: RunContext[CloseDeps]) -> str | None:
    return 'Month-end close is running: invoices cannot be marked paid until Monday.' if ctx.deps.closing else None

What you can do now

Grep your prompts for f-strings and .format(. Every interpolated fact becomes a deps field and an instructions function; every value that can change mid-conversation gets a name and on_change='append'.
