Capabilities: the unit of harness behavior

Everything chapters 2 to 5 built lives on one agent. A capability packages it once: instructions, tools, gates and hooks, attached to any agent. The built-ins, and whole agents like Coder, are made the same way.

Friday: a second agent

The climax of Part 2. The point: a tool copied without its rules is the failure; a capability carries the rules with it. Walk the four steps slowly, then the built-ins, the building blocks and Coder.

Offline, deterministic. Tool lists, notices and ledger writes are Pydantic AI 2.68's real behavior; the replies come from a stand-in model that answers from its page. code/part2/ch6_capabilities.py

Step 1 is the failure: the new agent got the tool without its rules, and wrote to the ledger during close. Once the rules travel with the tool, every agent that has one has the other.

The collections world, packaged

Capability has the decorators an agent has, so moving the code over is a change of prefix. Each highlighted line is a chapter: the received date (2), the close notice and the hidden, gated mark_paid (3), errors that say whose problem it is (3). Chapters 7 to 9 and Part 3 import this file. A capability can also contribute model settings, a fallback model, history processing and hooks around every request and tool call.

code/part2/billing_world.py · pydantic-ai 2.59+
from dataclasses import dataclass, field
from datetime import date
from decimal import Decimal

from pydantic_ai import Agent, DeferredToolRequests, ModelRetry, RunContext, ToolDefinition, ToolFailed, ToolOutput
from pydantic_ai.capabilities import Capability

from billing import FakeBilling, Invoice, LedgerUnavailable


@dataclass
class Deps:
    billing: FakeBilling
    received: date
    closing: bool = False  # month-end close is running
    ledger_changes: list[str] = field(default_factory=list)  # your sync job appends to this


billing_world = Capability[Deps](
    id='billing_world',  # names its instruction parts, so a change can be appended
    instructions='Amounts and invoice numbers come from our billing system, never from an email alone.',
)


@billing_world.instructions(name='received')  # chapter 2: the fact that anchors "this Friday"
def received_on(ctx: RunContext[Deps]) -> str:
    return f'This message was received on {ctx.deps.received:%A %Y-%m-%d}.'


@billing_world.instructions(name='close', on_change='append')  # chapter 3: a tool that leaves, said out loud
def close_notice(ctx: RunContext[Deps]) -> str | None:
    if ctx.deps.closing:
        return 'Month-end close is running until Monday: mark_paid is unavailable, so say so.'
    return None


@billing_world.instructions(name='ledger', on_change='append')  # Part 1: say what changed, at the end
def ledger_changes(ctx: RunContext[Deps]) -> str | None:
    if not ctx.deps.ledger_changes:
        return None
    return 'Changes in our ledger since this conversation started:\n' + '\n'.join(ctx.deps.ledger_changes)


@billing_world.tool  # facts are fetched from the source, not remembered
async def lookup_invoice(ctx: RunContext[Deps], invoice_number: str) -> Invoice:
    """Look up one of our invoices: amount, currency and status."""
    invoice = await ctx.deps.billing.get_invoice(invoice_number)
    if invoice is None:
        raise ModelRetry(f'There is no invoice {invoice_number}. Check the number in the email.')
    return invoice


async def hide_during_close(ctx: RunContext[Deps], tool_def: ToolDefinition) -> ToolDefinition | None:
    return None if ctx.deps.closing else tool_def


@billing_world.tool(requires_approval=True, prepare=hide_during_close)  # chapter 3: a person decides
async def mark_paid(ctx: RunContext[Deps], invoice_number: str) -> str:
    """Mark one of our invoices as paid."""
    await ctx.deps.billing.mark_paid(invoice_number, idempotency_key=ctx.tool_call_id)  # safe to retry
    return f'{invoice_number} is marked as paid.'


@billing_world.tool(requires_approval=True)
async def record_payment(ctx: RunContext[Deps], invoice_number: str, amount: Decimal) -> str:
    """Record a payment we received against one of our invoices."""
    if await ctx.deps.billing.get_invoice(invoice_number) is None or amount <= 0:
        raise ModelRetry('Use one of our invoice numbers and a positive amount, like 2060.00.')
    try:
        return await ctx.deps.billing.record_payment(invoice_number, amount, idempotency_key=ctx.tool_call_id)
    except LedgerUnavailable:
        raise ToolFailed('Nothing was recorded: the ledger is unavailable. Tell the customer it will be recorded later.')

from pydantic import BaseModel


class Installment(BaseModel):
    amount: Decimal
    due_date: date


class Promise(BaseModel, use_attribute_docstrings=True):  # chapter 5's answer form
    is_commitment: bool
    invoice_number: str | None = None
    installments: list[Installment] = []
    """One per amount and date the customer promised. A single payment is one installment."""
    doubts: list[str] = []
    """Anything in the email that doesn't add up, in your own words."""


collections = Agent(
    'anthropic:claude-sonnet-5-5',
    name='collections',
    deps_type=Deps,
    instructions="You handle customers' emails about their invoices with us, and record what they promise.",
    output_type=[ToolOutput(Promise), str, DeferredToolRequests],
    capabilities=[billing_world],
)
reminders = Agent(  # Friday's second job, in the same world
    'anthropic:claude-sonnet-5-5',
    name='reminders',
    deps_type=Deps,
    instructions='Draft the reminder for this invoice, or say why none should go out.',
    output_type=[str, DeferredToolRequests],
    capabilities=[billing_world, audit],  # the audit hook on this agent only
)

Building blocks for your own

Three ways in, from least to most code. Capability(...) with decorators, as above. Hooks() with @hooks.on.<event>, for one lifecycle hook, like an audit log on the reminders agent only. And a subclass of AbstractCapability when the rule needs configuration, tests or a package of its own: here the close rule, as a class that hides every writing tool.

code/part2/billing_world.py, a hook
import logging

from pydantic_ai.capabilities import Hooks

log = logging.getLogger('billing')
audit = Hooks[Deps]()


@audit.on.after_tool_execute
async def log_tool_calls(ctx: RunContext[Deps], *, call, tool_def, args, result):
    log.info('%s(%s) returned %r [call %s]', tool_def.name, args, result, call.tool_call_id)
    return result  # a hook may also change the result, or raise ModelRetry to send it back
code/part2/ch6_capabilities.py, a capability as a class
from pydantic_ai.capabilities import AbstractCapability
from pydantic_ai.messages import InstructionPart


@dataclass
class ReadOnlyDuringClose(AbstractCapability[Deps]):
    """The close rule as a class: hide every writing tool, and say so. Configurable, testable, publishable."""

    writing_tools: frozenset[str] = frozenset({'mark_paid', 'record_payment'})
    id: str | None = 'read_only_during_close'

    def get_instructions(self):  # what the model is told
        def notice(ctx: RunContext[Deps]) -> InstructionPart | None:
            if not ctx.deps.closing:
                return None
            return InstructionPart('Month-end close is running: you can read, not write.', name='close', on_change='append')

        return notice

    async def prepare_tools(self, ctx: RunContext[Deps], tool_defs: list[ToolDefinition]) -> list[ToolDefinition]:
        if not ctx.deps.closing:  # which tools this request offers
            return tool_defs
        return [t for t in tool_defs if t.name not in self.writing_tools]

If you subclassed or wrapped an agent to add logging or guards, a Hooks capability replaces it, and works on every agent.

from pydantic_ai.capabilities import LocalWorkspace
from pydantic_ai_harness.filesystem import FileSystem

reviewer = Agent(  # Coder's pieces, chosen yourself: reads code, runs tests, writes nothing
    'anthropic:claude-sonnet-5-5',
    instructions='Review the change in this repository. Run the tests. Do not edit files.',
    capabilities=[
        LocalWorkspace('.'),
        FileSystem(read_only=True),
        Shell(allowed_commands=['git', 'pytest']),
        RepoContext(),
        ClearToolResults(max_fraction=0.7, placeholder='[Cleared to save space. Read the file again if you need it.]'),
    ],
