Tools

The model decides whether to call a tool. Your code decides which tools a request offers, which wait for approval, and what the model hears back. Explain when a tool is unavailable.

Three rules for tools: when they're offered, who approves, what errors say

The point: three decisions in code, one line each. Then the gate that holds but says nothing, and the one line that fixes it on the same page.

Month-end close freezes the books. Invoice lookups are always allowed; marking an invoice paid needs approval and is unavailable during close. Recording received money with record_payment gets its own approval in chapter 6.

Four one-line rules: prepare= decides whether to offer a tool, requires_approval=True requests human approval, ModelRetry returns bad arguments as feedback, and ctx.tool_call_id makes writes safe to retry.

Offered or not: prepare. Runs or waits: requires_approval. Talks back: ModelRetry.

The agent and its three rules, from ch3_tools.py
agent = Agent(
    'anthropic:claude-sonnet-5-5',
    deps_type=Deps,
    instructions="You handle customers' emails about their invoices with us.",
    output_type=[str, DeferredToolRequests],  # a run can end by asking a person to approve a call
)


@agent.tool
async def lookup_invoice(ctx: RunContext[Deps], invoice_number: str) -> Invoice:
    """Look up one of our invoices: amount, currency and status."""
    invoice = await ctx.deps.billing.get_invoice(invoice_number)
    if invoice is None:
        raise ModelRetry(f'There is no invoice {invoice_number}. Check the number in the email.')
    return invoice


async def hide_during_close(ctx: RunContext[Deps], tool_def: ToolDefinition) -> ToolDefinition | None:
    return None if ctx.deps.closing else tool_def  # None: this request doesn't offer the tool


@agent.tool(requires_approval=True, prepare=hide_during_close)  # a person decides; gone during close
async def mark_paid(ctx: RunContext[Deps], invoice_number: str) -> str:
    """Mark one of our invoices as paid."""
    await ctx.deps.billing.mark_paid(invoice_number, idempotency_key=ctx.tool_call_id)  # safe to retry
    return f'{invoice_number} is marked as paid.'

The tool that left

During close, a colleague asks the agent to mark INV-2041 paid. The model has used mark_paid before, so it tries again. Step through what happens.

  1. 1
    model → tool call
    mark_paid({"invoice_number": "INV-2041"})
  2. ×
    back to the model: your code didn't offer it
    model reads: {"error":"Unknown tool name: 'mark_paid'. Available tools: 'lookup_invoice'"}
  3. 2
    the reply drafted for Dana
    model says:  I wasn't able to mark INV-2041 as paid. Please try again later.
  4. +
    add one line when close starts
    Month-end close is running: mark_paid is unavailable, so say so.
  5. ✓
    the reply drafted for Dana now
    model says:  Month-end close is running, so I can mark INV-2041 paid on Monday.

Nothing was written either time because the tool was not offered (ledger writes: []). The difference is what the model tells Dana: without an explanation, it says to try again. In Part 1 chapter 2, none of 80 conversations noticed a silently removed tool; one explanatory line fixed this for most models. Models may also use another tool to get the same result when one is hidden without explanation: Part 3, chapter 4 probes this.

Offline, deterministic. The "Unknown tool" result and the ledger writes are Pydantic AI 2.68's real behavior. The replies come from a stand-in model that answers from its page; what real models did with each page is Part 1 chapter 2's measurement.

A person approves the call first

With requires_approval=True, the tool cannot run without approval. The run ends with DeferredToolRequests, listing pending calls. Your app stores the conversation (chapter 4), shows the request to a person, then starts a new run with the stored conversation and deferred_tool_results=. Errors that say who has to fix it

Recording Dana's payment can fail in three ways. The model needs to know which one to decide what to tell her:

What went wrongRaiseWhat the model does
Its mistake: an unknown invoice, a bad amountModelRetryFixes the call and tries again, within the tool's retry budget
Your system failed: the ledger timed outToolFailedTells the customer it will be recorded later; recorded as failed on your traces
A normal answer, even a "no"return a stringReads it as data
code/part2/ch3_tools.py, three worlds
from decimal import Decimal

from pydantic_ai import ToolFailed

from billing import WIRE_RECEIVED, LedgerUnavailable


@agent.tool
async def record_payment(ctx: RunContext[Deps], invoice_number: str, amount: Decimal) -> str:
    """Record a payment we received against one of our invoices."""
    if await ctx.deps.billing.get_invoice(invoice_number) is None or amount <= 0:
        raise ModelRetry('Use one of our invoice numbers and a positive amount, like 2060.00.')  # its mistake
    try:
        return await ctx.deps.billing.record_payment(invoice_number, amount, idempotency_key=ctx.tool_call_id)
    except LedgerUnavailable:  # our outage: not the model's to fix, and nothing happened
        raise ToolFailed('Nothing was recorded: the ledger is unavailable. Tell the customer it will be recorded later.')
// output

If you return "error: ledger down" as a string, the model may say the payment succeeded and monitoring counts the call as successful because the function returned normally.

Let the capability pick the provider's own tool

For web search, fetching a page, generating images or connecting an MCP server, add the capability rather than writing the tool: WebSearch, WebFetch, ImageGeneration or MCP. Each uses the provider's own tool when the model has one, since models are trained on those, and can fall back to a local version on models that don't (for web search, local='duckduckgo'). Switching models then doesn't break the agent. Web search shows the pattern.

What you can do now

Gate writing tools with requires_approval or prepare, key writes on ctx.tool_call_id, explain unavailable tools, and classify failures as ModelRetry, ToolFailed, or normal answers.

See it in Logfire. Each request lists offered tool definitions, including when mark_paid is missing. Approval ends the run without a tool result; ModelRetry adds a request with your error text.
