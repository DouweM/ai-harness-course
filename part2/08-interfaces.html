Who holds the history

By default a UI adapter trusts the frontend: the browser sends the whole conversation each turn, and the agent runs on it. That's convenient, and it means the browser holds the model's world. Here a client sends Tuesday's thread back with one edit: the lookup result now says the invoice is paid.

What the model read

The edited one. To the model it's its own lookup, and Part 1 showed it believes every line of its history.

// output, recorded by verify.py
manage_message_history='client': the lookup on the model's page says 3900.00, paid

A client can't call your tools, but under the default it can write what they returned. Fine for a single-user notebook; not for an app where the customer's browser talks to an agent that can mark invoices paid.

The fix: the server holds the history

With manage_message_history='server' only the client's new turn is used, and the history comes from your store. A conversation_store on the adapter does the loading and saving for you.

Approvals in the frontend

Chapter 3's approval reaches a UI as part of the protocol. With AG-UI the run finishes with an interrupt: what to ask, and the shape of the answer. Nothing is written until the person answers.

code/part2/ch8_interfaces.py, an approval over AG-UI
from pydantic_ai.ui.ag_ui import AGUIEventStream


async def asks_to_mark_paid(messages: list[ModelMessage], info: AgentInfo):
    yield {0: DeltaToolCall(name='mark_paid', json_args='{"invoice_number": "INV-2041"}', tool_call_id='call_1')}


async def what_the_frontend_gets() -> None:
    stream = AGUIEventStream(thread_id='dana', run_id='monday')
    deps = Deps(billing=FakeBilling(), received=WIRE_RECEIVED)
    with collections.override(model=FunctionModel(stream_function=asks_to_mark_paid)):
        async with collections.run_stream_events('The rest is paid too. Mark INV-2041 paid.', deps=deps) as events:
            async for event in stream.transform_stream(events):
                last = event
    for interrupt in last.outcome.interrupts:  # the run is over, and says why: a person has to approve
        print(' ', interrupt.message, interrupt.response_schema['required'])
    print('ledger writes:', deps.billing.writes)


asyncio.run(what_the_frontend_gets())

And the rest

agent.to_web() serves a local chat for trying an agent; to_cli_sync() a terminal one. An MCP server can expose the agent as a tool for other agents. And a phone call is a realtime session on the same agent: same tools, same capabilities, ordinary history at the end.

from pydantic_ai import Agent

voice = Agent(instructions='You answer billing questions by phone. Keep answers short.')


async def call(audio_chunk: bytes) -> None:
    async with voice.realtime('openai:gpt-realtime').session() as session:  # same tools, same capabilities
        await session.send_audio(audio_chunk)  # mono PCM16 at session.audio_input_sample_rate
        async for event in session:
            ...  # speech out, tool calls, turn boundaries; session.all_messages() is ordinary history

What you can do now

For each door your agent sits behind, ask who holds the history. If it's a browser or another service, switch to manage_message_history='server' or a conversation store.
